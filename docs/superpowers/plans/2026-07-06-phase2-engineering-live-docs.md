# Phase 2 — `/engineering` Live Docs Section — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a native, designed `/engineering` public section to pinwiz.ai that renders a curated subset of the repo's real docs as first-class MudBlazor pages — indistinguishable in look-and-feel from the rest of the site, never reading as autogenerated.

**Architecture:** A `docs/engineering-manifest.json` curation contract drives an MSBuild target that embeds exactly the listed markdown files (+ all ADRs) into the Web assembly. `IEngineeringDocsProvider` loads/parses them at startup (no runtime I/O). `MarkdownComponentRenderer` walks the Markdig AST and emits MudBlazor components via `RenderTreeBuilder` — no `MarkupString`, preserving the app's hard XSS constraint. Pages are static SSR like `/about`. A merged docs change redeploys the image (deploy.yml gains `docs/**`), making the section live.

**Tech Stack:** Blazor Web App (.NET 10, static SSR), MudBlazor (ADR-0008), Markdig (new NuGet), xUnit + bUnit, Playwright (a11y/snapshot), pre-rendered Mermaid SVG.

## Global Constraints

- MudBlazor strict (ADR-0008) — use `MudText`, `MudLink`, `MudCard`, `MudList`, and the shared `App*` wrappers (ADR-0046). `MudTable`/`MudSimpleTable` banned at the page layer; use `AppDataGrid`.
- **No `MarkupString` anywhere** — all content via `RenderTreeBuilder.AddContent` (HTML-encoded). Same constraint as `Components/Wizard/MarkdownTokenizer.cs`.
- CSP is enforced — no CDN scripts, no inline `<script>` outside `App.razor`, no `unsafe-eval`. Diagrams are pre-rendered SVG committed to `wwwroot/img/engineering/` (the `/about` pattern), hash-pinned by the `PreRenderedDiagramTests` mechanism.
- Static SSR pages: no `@rendermode` on these pages (match `/about`).
- Markdig addition requires no locked-mode churn for the Web project — `PinballWizard.Web.csproj` already sets `<RestorePackagesWithLockFile>false</RestorePackagesWithLockFile>`. Add the version to `Directory.Packages.props` (central package management).
- Personal identity commits; branch `docs/refresh-and-docs-agent`.
- Public-facing copy honors community-resource posture (ADR-0027): explain honestly, route outward, no engagement-metric framing.

```csharp
using System.Text.Json;

namespace PinballWizard.Web.Engineering;

public sealed record EngineeringManifestEntry(string Slug, string SourcePath, string Title, string Group, int Order);

public static class EngineeringManifest
{
    public const string ManifestRelativePath = "docs/engineering-manifest.json";

    public static IReadOnlyList<EngineeringManifestEntry> Load(string repoRoot)
    {
        var path = Path.Combine(repoRoot, ManifestRelativePath.Replace('/', Path.DirectorySeparatorChar));
        using var stream = File.OpenRead(path);
        using var doc = JsonDocument.Parse(stream);
        var list = new List<EngineeringManifestEntry>();
        foreach (var e in doc.RootElement.GetProperty("docs").EnumerateArray())
        {
            list.Add(new EngineeringManifestEntry(
                e.GetProperty("slug").GetString()!,
                e.GetProperty("sourcePath").GetString()!,
                e.GetProperty("title").GetString()!,
                e.GetProperty("group").GetString()!,
                e.GetProperty("order").GetInt32()));
        }
        return list;
    }
}
```

- [ ] **Step 3: Implement the renderer**

Walk the Markdig `MarkdownDocument` block list. Emit via `RenderTreeBuilder`:
- `HeadingBlock` → `MudText` with `Typo` mapped by level (`h1→Typo.h4`, `h2→Typo.h5`, `h3→Typo.h6`, else `Typo.subtitle1`) to match the site scale.
- `ParagraphBlock` → `MudText Typo="Typo.body1"` with inline children rendered recursively.
- `ListBlock` → `AppBulletList` containing an `AppBulletItem` per `ListItemBlock`.
- `Table` (pipe table) → `MudSimpleTable`-free path: build a `MudTable`-less styled table using `<table class="mud-table-root eng-table">` header/rows composed of `MudText` cells; OR the simplest compliant option — a `MudTable<>` is page-layer-banned, so render a plain semantic `<table>` styled by a scoped CSS class. Use plain `<table>`/`<thead>`/`<tbody>` elements (allowed; the ban is on `MudTable`/`MudSimpleTable` components, not HTML tables) with `AddContent` cells.
- `FencedCodeBlock`/`CodeBlock` → `<pre class="eng-code"><code>` with `AddContent` (encoded) text.
- Inline `LiteralInline` → `AddContent` (encoded). `EmphasisInline` → `<em>`/`<strong>`. `LinkInline` → `MudLink`: resolve via `slugLinkResolver(url)`; if non-null use it (internal route), else use the URL as-is; external URLs get `Target="_blank"`.
- Never call `AddMarkupContent`. Any unhandled inline falls back to its literal text via `AddContent`.
