# Design: Documentation Refresh + Live `/engineering` Docs + Push-Triggered Docs Agent

**Date:** 2026-07-06
**Status:** Approved (brainstorming) — pending implementation plan
**Branch:** `docs/refresh-and-docs-agent` (worktree `.worktrees/docs-refresh-agent`)

## Problem

Three related gaps, discovered during a documentation audit:

1. **Docs have drifted.** A staleness audit found 15 concrete gaps between the
   shipped code and the human-authored docs. The two worst are customer-facing:
   `README.md` still claims `pinwiz.ai` is not yet live (reality: Phases 2–6
   shipped, Phase 7 active), and `docs/knowledge-sources.md` says Tilt Forums
   ingestion is permission-gated when it shipped (ADR-0050, PRs #670/#675).
2. **Drift re-accumulates silently.** Existing doc-conformance tests
   (`DocConformanceTests`, `StandardsConformanceTests`) guard *structure*
   (project names, ADR index, rule uniqueness) but nothing guards *content
   freshness*. Every one of the 15 gaps passes the existing suite.
3. **The docs aren't a showcase surface.** The engineering docs — the actual
   product story for a prospect — live only as markdown in the repo and as
   external GitHub links from `/about`. There is no on-site, designed
   presentation of them.

This is a customer-facing reference app; stale or invisible docs undercut the
whole point (see `CLAUDE.md` "Documentation is part of the product").

## Goals

- Bring the docs back to truthful (one-time refresh pass).
- Keep them truthful automatically as code merges (push-triggered agent).
- Surface a curated subset as a native, designed `/engineering` section on
  pinwiz.ai that reads as part of the product, not as autogenerated output.
- Document *why* the docs-agent is a CI agent and not a Foundry product agent
  (ADR-0051), so the two-category split is a recorded decision, not tribal
  knowledge.

## Non-Goals

- Mirroring *all* docs publicly. Internal-operational docs (runbooks,
  cost-tracking, threat-model, build-spec) stay repo-only.
- The agent authoring ADRs or decision-log entries autonomously (it flags them
  for a human instead).
- Client-side Mermaid on the site (CSP forbids it; we keep the pre-rendered-SVG
  pattern).
- A public "devlog"/generated-prose surface. The site renders the *real* docs.

---

## Phasing

Built in dependency order — the agent and the live section must start from
truthful docs, so the refresh lands first.

- **Phase 1 — Docs refresh pass** (supervised, one PR).
- **Phase 2 — `/engineering` live docs section** (build-time embed + native render).
- **Phase 3 — `docs-agent.yml`** push-triggered updater + guard + auto-merge.
- **Cross-cutting — ADR-0051** documenting the agent-category boundary.

Each phase is independently shippable and independently valuable.

---

## Phase 1 — Docs refresh pass

Fix the 15 audited staleness gaps. Executed by parallel subagents grouped by
doc surface (no two agents touch the same file), landing as **one docs-only PR**
(cheap CI: only `docs.yml`, `sanitization.yml`, `claude-config-guard.yml` run).

### Work groups (parallelizable)

- **A — Live-status corrections:** `README.md` (Phase 6→7 status, "goes live
  after H-chain" → live), `docs/vision.md` if it echoes the same, README doc-map
  phase line.
- **B — Source tables:** `docs/knowledge-sources.md` + `CLAUDE.md` scraper table
  — Tilt Forums (active), Pinball Brothers Freshdesk scraper (#663), IPDB
  reference fields on `Machine` (#11a3a8d), Freshdesk posture.
- **C — Build-spec / feature coverage:** `docs/build-spec.md` phase entries for
  ACA per-scraper jobs + admin schedule editor (#681), OCR activation (#669),
  GridSearch unification (#680), DocumentLinker cross-year reissue families
  (#678), bugfinder crawler (#671); `guardrails.md` locked-decisions + build-spec
  scope for ADR-0049 findability program.
- **D — Standards + stale-file triage:** `ENGINEERING_STANDARDS.md` §7.1 E2E
  table (add bugfinder); triage `PHASE5-DRIFT-AUDIT.md`, `quality-bar.md`,
  `self-healing-agent-and-ai-roadmap.md` (mark archived/dated or refresh).

### Decision-log entries (supervised exception)

Several gaps are *missing decision-log entries* (OCR activation rationale, Tilt
Forums posture reversal, per-scraper-jobs decision, Freshdesk posture, GridSearch
architecture, ManufacturerSlug backfill). The "agent never authors decisions"
rule (Phase 3) applies to the *autonomous* agent. For this *supervised* pass, I
draft these entries in the same PR, each clearly marked as AI-drafted in the PR
description, for the user to accept, edit, or strike. Provenance stays human
because a human reviews before merge.

### Exit criteria

- All 15 gaps closed or explicitly deferred with a reason in the PR.
- `docs.yml` link + Mermaid checks pass.
- (New) content-freshness conformance test seeds — see Phase 3 guard — are not
  required for Phase 1 but the refresh must not regress existing conformance
  tests.

## Phase 2 — `/engineering` live docs section

A native, designed public section — sibling to `/about`, which stays as the
narrative front door and gains an "Explore the engineering docs" link.

### Information architecture

| Route | Purpose |
|---|---|
| `/engineering` | Hand-designed landing: section cards (`AppSummaryCard`) per doc group, latest-ADRs strip, freshness metadata (source commit + deploy date), one-sentence "two kinds of agents" framing linking ADR-0051. |
| `/engineering/docs/{slug}` | Rendered curated doc pages. |
| `/engineering/adr` | Designed ADR index (`AppDataGrid`: number, title, status, date) replacing link-out-to-GitHub. |
| `/engineering/adr/{number}` | Individual ADR pages. |

Nav: one new `NavRailItem` ("Engineering") in `MainLayout` `PublicNav`; one
`MudLink` in `BrandFooter` Navigate column. Pages are static SSR (no render
mode), matching `/about` — fast, SEO-friendly, CSP-clean.

### Curation manifest — single source of truth

`docs/engineering-manifest.json` is the only curation point. Each entry:
`{ slug, sourcePath, title, group, order }`. Adding a doc to the public site =
one manifest line. **Initial curated set:** `vision.md`,
`ai-development-model.md`, `learning-from-failure.md`, `architecture-v2.md`,
`glossary.md`, plus **all ADRs** (`docs/adr/NNNN-*.md`). Internal-operational
docs are intentionally excluded.

### Content pipeline (build-time embed)

- Manifest-listed files are embedded in the Web assembly at build time via an
  `<EmbeddedResource>` glob driven by the manifest (an MSBuild target reads the
  manifest and includes exactly its `sourcePath` set + the ADR glob). The
  Dockerfile build context is repo root, so `docs/` is reachable at publish.
- `IEngineeringDocsProvider` (Web project) loads and parses embedded docs at
  startup; **no runtime file or network I/O**. The deployed image is
  self-consistent — the docs it shows are the docs it was built from.
- **Freshness metadata:** build stamps the source commit SHA + build date into
  the provider (MSBuild property → assembly metadata), surfaced on `/engineering`.

### Native rendering (the "not autogenerated" requirement)

Markdown is rendered into MudBlazor components, **not** into an HTML blob.

- Markdig parses markdown → AST. A `MarkdownComponentRenderer` walks the AST and
  emits components via `RenderTreeBuilder`:
  - headings/paragraphs → `MudText` with the site's typographic scale
  - lists → `AppBulletList` / `AppBulletItem`
  - tables → Mud-styled table matching `AppDataGrid` visual language
  - code blocks → styled `<pre>` with the site's mono treatment
  - links → `MudLink`; relative repo links whose target is in the manifest are
    rewritten to their `/engineering/...` equivalent, otherwise pointed at the
    GitHub source.
- **No `MarkupString`, ever** — preserves the app's existing hard XSS constraint
  (the same one enforced on the wizard `MarkdownTokenizer`). Raw HTML embedded
  in markdown renders as escaped text.
- Every page uses `AppPageHeader` (title + subtitle + breadcrumbs), so an
  `/engineering` page is visually indistinguishable in chrome from any other
  page on the site.

Markdig is added as a NuGet dependency (packages.lock regeneration required —
see `reference_locked_lockfile_transitive_gotcha`).

### Diagrams

Pre-rendered SVG pattern (existing): Mermaid source in `docs/diagrams/`, rendered
offline by mermaid-cli, SVG committed to `wwwroot/img/engineering/`,
hash-pinned. A conformance test asserts every ```` ```mermaid ```` block in a
manifest doc has a corresponding rendered SVG. `docs.yml` already validates
Mermaid syntax.

### Deploy coupling (what makes it "live")

`deploy.yml` gains `docs/**` to its trigger `paths:`. A merged docs PR (whether
human or agent) redeploys the Web image, propagating doc changes to the site.
This is the link that turns "agent updates docs" into "site updates itself."

### Testing

- Manifest conformance: every entry resolves to an embedded file; every embedded
  doc parses + renders without error.
- bUnit render tests for `MarkdownComponentRenderer`: headings, lists, tables,
  link rewriting, escaped-HTML case.
- One Playwright a11y + snapshot registration for `/engineering`.
- Extend `tools/docs/check-links.mjs` to validate manifest slugs resolve.

## Phase 3 — `docs-agent.yml` (push-triggered updater)

### Category

This is a **CI development-automation agent** (Claude Code in GitHub Actions),
**not** a Foundry product agent. See ADR-0051. It follows the *exact* existing
pattern of `claude.yml` and `pr-feedback-triage.yml`:
`anthropics/claude-code-action@v1`, keyless GitHub-OIDC → Anthropic WIF token
exchange (ADR-0047), Actions Variables already configured. No new secrets.

### Triggers (one job)

- **`push` to `main`**, paths `src/**`, `infra/**`, `.github/workflows/**` —
  per-merge incremental. Prompt receives the merged commit range
  (`${{ github.event.before }}..${{ github.sha }}`) + docs inventory; instruction
  is: *does this change make any descriptive doc untruthful? If yes, fix those
  docs; if no, exit without a PR.* Most merges no-op.
- **`schedule` weekly** (offset minute, like `canary.yml`) — full-sweep audit of
  the week's commits vs. the doc set; safety net for missed per-merge runs.
- **`workflow_dispatch`** — manual test/backfill.

Permissions: `contents: write`, `pull-requests: write`, `id-token: write`.
Concurrency group `docs-agent-main`, **queued not cancelled** (each merge
deserves analysis). The 10-minute WIF token bounds per-run scope; if weekly
sweeps hit the ceiling, extend token lifetime in the Anthropic Console (a
documented settings change, not a workaround per `timeout-debugging` rule).

### Agent contract (prompt + mechanically enforced by the guard)

- **May edit:** `docs/**` *except* `docs/adr/**` and `docs/decision-log.md`;
  `README.md`; `CLAUDE.md`; `docs/engineering-manifest.json`.
- **Must never:** author ADRs or decision-log entries; touch code; edit
  workflows. When a merge looks decision-worthy, the agent adds a **"Human
  follow-ups"** section to the PR description naming the missing ADR /
  decision-log entry (flag, don't author).
- **PR shape:** branch `docs-agent/<sha>`, `claude-code` label, description
  records provenance (commit range analyzed, each doc touched + why), enables
  `gh pr merge --auto --squash`.

### Safety fence: `docs-agent-guard.yml` (required check)

Runs on all PRs; **instantly passes** when the head branch isn't `docs-agent/*`
(so no noop-companion file needed). For `docs-agent/*` branches, it **fails if
any changed file falls outside the allowlist** above. This is what makes
auto-merge safe: the agent's authority is bounded *mechanically*, not by prompt
obedience. Auto-merge fires only when the guard + `docs.yml` +
`sanitization.yml` + `claude-config-guard.yml` all pass.

### Loop prevention + failure visibility

- **No self-retrigger, structurally:** merged agent PRs touch only docs paths →
  don't match the push trigger's `src/**`/`infra/**` path filter → no loop.
- **Failure is loud:** on run failure the workflow opens/comments a pinned issue
  (same pattern as `canary.yml`), consistent with the no-masking-fallbacks
  invariant (#17). Silent breakage cannot accumulate.

### Auto-merge decision (recorded)

User chose auto-merge-when-checks-pass over human-review-always. The guard +
sanitization + link/Mermaid checks are the compensating controls that make the
"docs self-heal on every merge" showcase story safe. Trade-off accepted: a
plausible-but-wrong *descriptive* edit within the allowlist could reach the site
unreviewed; mitigations are (a) the agent cannot touch decisions/code, (b)
weekly human-visible PR history, (c) the pinned-issue failure surface.

## Cross-cutting — ADR-0051: two agent categories

**Title:** "Two agent categories: Foundry product agents vs. Claude Code CI
automation agents." **Status:** Accepted.

Records the boundary and the decision rule for classifying any future agent:

| | Product agents (Foundry) | Dev-automation agents (Claude Code CI) |
|---|---|---|
| Trigger | End users on pinwiz.ai | Git events (push/PR/schedule) |
| Acts on | User questions → RAG/tools | Repo diffs → markdown |
| Runtime | Deployed ACA workload, always-on | Ephemeral Actions runner |
| Needs | Managed identity, eval, model routing, SLOs | Repo checkout, git, `gh` PR |
| Blast radius | Customer answer quality | A PR gated by checks |

Key reasoning captured: the two are *one solution each to two different
problems*, not two solutions to one. Shared invariants hold at the layer below
(both model-agnostic by construction; both keyless — Foundry
`DefaultAzureCredential`, CI OIDC→WIF). Precedent: `claude.yml`,
`pr-feedback-triage.yml` are already category-2; the docs-agent is the third
instance, not a new pattern. Forcing the docs-agent into Foundry would require
reinventing CI plumbing (repo PAT, git, PR creation) inside a product-runtime
orchestrator.

**Echoed (not duplicated) in:** `docs/ai-development-model.md` ("Two kinds of
agents" prose section, docs-agent as worked example); `/engineering` landing
page (one sentence + ADR link); `docs-agent.yml` header comment (points back to
ADR-0051 for "why not Foundry"). `docs/adr/README.md` index updated (guarded by
`AdrReadme_IndexesEveryAdrFile`).

## Isolation / units summary

- **`docs/engineering-manifest.json`** — curation contract. Consumers:
  MSBuild embed target, `IEngineeringDocsProvider`, link checker, `/engineering`
  IA. Changing the curated set = editing one file.
- **`IEngineeringDocsProvider`** — loads/parses embedded docs; hides embedding
  mechanism from pages. Testable without the web host.
- **`MarkdownComponentRenderer`** — AST → MudBlazor components; pure transform,
  unit-testable via bUnit, no I/O.
- **`docs-agent.yml`** + **`docs-agent-guard.yml`** — the agent and its fence
  are separate files; the guard is independently testable and independently the
  security boundary.
- **ADR-0051** — the decision record; the workflow comment and dev-model doc
  depend on it but it depends on nothing.

## Risks

- **Markdig transitive lockfile churn** — regenerate `packages.lock.json`, run
  `dotnet restore --locked-mode` before push (`reference_locked_lockfile_...`).
- **Agent misreads a diff** — bounded by guard allowlist + auto-merge compensating
  controls above; worst case is a wrong descriptive line, not a wrong decision or
  code change.
- **WIF token 10-min ceiling on weekly sweeps** — measure first; extend lifetime
  in Console only with justification.
- **New required check (`docs-agent-guard`) blocking code PRs** — avoided by the
  instant-pass-when-not-agent-branch design (no noop companion needed).
